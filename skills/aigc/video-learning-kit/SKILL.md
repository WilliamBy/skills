# 长视频字幕整理与学习组件

## 目标与边界

将原始字幕转换为可追溯、可阅读的整理稿，再按需生成配套学习材料。把任务分成两层：

1. **整理稿是转写层**：保留原话、原顺序、原例举和现场语气；只机械清洗与划分版式。
2. **学习组件是归纳层**：可以总结、提炼、设问，但不得反向修改整理稿，也不得虚构源材料没有的结论。

始终遵循：

- 不依据领域知识猜测原意，不替换疑似识别错误的术语、产品名、数字、版本号或英文拼写。
- 不添加承上启下句、解释、背景、例子、结论或旁白。
- 不把“听起来更合理”当作修改依据。拿不准时保留原字。
- 不用摘要代替全文整理，不删除仍承载内容的离题、重复论证、问答、口误或情绪表达。
- 不因生成学习组件而污染整理稿；两者必须输出为不同文件。

## 路由

- 输入原始字幕，要求文字稿、整理稿或学习套件：先执行[完整整理流程](#完整整理流程)。
- 已有本技能生成的整理稿，要求笔记、提要、闪卡或练习：读取[学习组件规范](references/learning-components.md)，只生成指定组件。
- 已有其他文字稿，要求学习组件：先确认其是否忠实全文；若不确定，在交付说明中标记“基于现有稿件，未核对原始字幕”。
- 只要摘要而不要全文：可以直接摘要，但不得将摘要命名为“整理稿”或“逐字稿”。

## 完整整理流程

### 1. 接收与检查

读取完整字幕，识别编码、字幕格式、元信息位置、原始章节标记和正文起点。不要只看开头就推断全文字幕结构。

优先使用本技能的脚本处理；仅在字幕包含脚本不支持的结构时扩展脚本，并继续保持确定性规则。不要把长字幕直接交给模型逐句重写。

输出目录默认为当前工作区中的独立目录，避免覆盖原字幕和既有整理稿。文件命名：

```text
<视频名>-整理稿.md
<视频名>-整理稿-校对报告.md
<视频名>-学习笔记.md
<视频名>-学习提要.md
<视频名>-记忆闪卡.md
<视频名>-课后习题.md
<视频名>-work/
```

不要未经请求同时生成全部学习组件。默认只交付整理稿与校对报告；用户要求“学习套件”时再生成全部组件。

### 2. 确定性机械清洗

使用 `scripts/clean_subtitles.py`：

```bash
python scripts/clean_subtitles.py "<原始字幕路径>" --output-dir "<工作目录>"
```

优先采用环境中受管理的 Python 绝对路径。脚本仅使用 Python 标准库，支持 UTF-8/UTF-8-SIG/UTF-16/GB18030 文本、SRT、VTT、纯文本字幕及 `[章节]` 标记。

脚本产出：

- `cleaned_sentences.tsv`：带稳定句子编号的清洗结果，供推理分段使用。
- `cleaned_transcript.md`：仅按原始章节或固定长度分段的中间稿，不是最终整理稿。
- `manifest.json`：源文件、参数、规则和统计信息。
- `metadata.txt`：被移除的页首元信息、时间戳和序号等，供审计。
- `review.txt`：脚本无法确定但保留原样的内容。

默认清洗规则必须保持保守：

1. 删除 SRT/VTT 序号、时间轴、WEBVTT 声明和纯格式标签。
2. 对首个 `[章节]` 之前的独立页首信息，仅删除明确的标题、URL、上传者/发布时间行；无章节标记时不批量猜测页首，只删除 URL 等明确元信息。
3. 合并相邻且完全相同的字幕行；保留非完全相同的近似句，以防误删语义。
4. 仅删除独立出现的口播填充词和明显的机械重复，具体白名单见脚本；不做自由文本替换。
5. 依据原句末标点合并字幕软换行；超长口播句只在原有逗号处切分，不删改词语，不为“通顺”而改写。
6. 保留所有原始术语、英文、数字和无法辨认的片段；列入复核而非订正。
7. 不自动修复语法，不自动补主语，不自动纠正同音字。

需要放宽规则时，先由用户明确指定规则；不要临场扩大清洗词表。

### 3. 推理划分章节与段落

读取 `cleaned_sentences.tsv`。以句子编号 `S0001` 等为最小操作单元，只添加 Markdown 标题与空行，**保持句子文本逐字不变**。

- 通读全文后，根据话题转换、讲者明示的结构、现场演示切换和问答轮转划分章节。
- 优先利用原章节标记，但可在其内部细分；不得为了标题整齐而移动句子。
- 标题用短名词短语概括本段内容。标题可以归纳，正文不可归纳。
- 一段聚焦一个连续话题，通常 2–6 句；现场问答可独立成段。
- 不添加“这一章说明了……”等导语，不写段落摘要，不插入来源不明的舞台动作。
- 文档开头只保留视频标题及一句固定整理说明，不生成目录、内容摘要或核心观点，除非用户另行要求。
- 在句内不插入或删除文字，不将两句合并重写为一句；可换段，也可将一个清洗句独立成段，但不得拆改句内文字。

采用先写结构计划、再组装的方式，避免逐段自由重写。长文分批读取，但维护全局已处理句子编号，防止漏句、重句和乱序。

固定整理说明：

> 本文由原始字幕经保守机械清洗后整理，仅添加章节与段落，不作术语订正或语义改写。原始用词及可能存在的识别误差均予保留。

### 4. 保真校验

使用 `scripts/check_transcript.py`：

```bash
python scripts/check_transcript.py "<工作目录>/cleaned_sentences.tsv" "<最终整理稿.md>" --output "<校对报告.md>"
```

校验分两部分：

- **结构校验**：按句子编号检查漏句、重句、乱序及句内字符变化。此项必须全部通过。
- **来源诊断**：检查标题、说明与正文分区，报告原字幕元信息和需要人工听辨的片段。字符 n-gram 仅可作为诊断，不得代替逐句一致性检查，也不得通过“覆盖率达标”宣告内容无误。

若结构校验失败，按报告修复整理稿后重新运行。不要在最终回复中只给平均覆盖率；应说明是否存在漏句、重句或改写。

### 5. 交付整理稿

交付最终整理稿和校对报告，并明确：

- 采用了哪些机械清洗规则。
- 是否仍有无法确定的字幕内容。
- 未做术语订正、事实核查和语义补写。
- 原字幕本身不是可靠事实来源；需要准确术语或数字时，应结合音频或权威材料另行核验。

## 学习组件

从最终整理稿提取内容，按[学习组件规范](references/learning-components.md)生成。可用 `scripts/source_index.py` 建立带章节与段落定位的只读索引：

```bash
python scripts/source_index.py "<最终整理稿.md>" --output "<工作目录>/source_index.json"
```

共同要求：

- 只以整理稿为依据，不引入外部资料作为视频观点。
- 区分“讲者观点/演示”“可由原文直接支持的事实”“整理者推断”；推断默认不写。
- 每个核心结论、闪卡和习题答案均带章节或段落定位；没有依据则不生成。
- 对疑似字幕错误不自行纠正。必要时写“原字幕如此，术语待核”。
- 复习内容强调少而准，不追求覆盖每一句；整理稿仍承担完整内容保存职责。
- 答案先独立完成，再与对应章节核对，避免问题与答案脱节。

组件侧重点：

- **学习笔记**：分层总结概念、论证、例子、流程和结论，服务第一次系统学习。
- **学习提要**：一页式重点地图，服务快速浏览和考前回忆。
- **记忆闪卡**：最小知识点、一卡一问，优先主动回忆而非再认。
- **课后习题**：检索练习、理解、应用与反思分层，附答案和出处。

## 完成条件

只有满足以下条件才交付：

- 原始字幕未被修改。
- 最终整理稿通过逐句结构校验。
- 正文没有模型新增的衔接句、解释或术语修正。
- 学习组件与整理稿分开保存，并附可回查定位。
- 所有交付文件真实写入后，再统一展示文件。
